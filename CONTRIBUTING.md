# Contributing

## Build and run

Requires Node.js 22 or newer.

```bash
npm install
npm start          # run from source
npm test           # route, module, privacy and updater tests
npm run app:mac    # macOS: just the .app in dist/, fastest for local use
npm run dist:mac   # or dist:win / dist:linux: installers in dist/ (Windows: add --x64 or --arm64)
```

Build each platform on that platform: macOS cannot be cross-built, and the Windows installer needs Wine elsewhere. The release workflow does all of them on native GitHub runners.

## Tests

`npm test` runs everything in `test/` with Node's built-in test runner; CI runs it on Linux, macOS and Windows.

- `routes.test.js`: which URLs stay in the app, bounce to the inbox, download or open in the browser.
- `modules.test.js`: settings validation and migration, app-lock password hashing, Do Not Disturb, focus schedule, update version checks.
- `self-update.test.js`: install detection, and the macOS/Linux and Windows swap helpers run for real against throwaway folders.
- `privacy.test.js`: enforces the claims in [PRIVACY.md](PRIVACY.md). It fails if code runs scripts in Facebook's pages, gives them a preload or IPC, reads cookies, inspects traffic, makes network requests outside `updater.js`, or weakens isolation, permissions or fuses. Change PRIVACY.md before relaxing a rule.

## How the code is organised

| File | Purpose |
|---|---|
| `src/main.js` | Shell window, sessions and permissions, navigation guards, accounts, menus, wiring |
| `src/account-view.js` | One account: a view with its own session partition, unread count from the title |
| `src/routes.js` | Route policy (pure URL matching) |
| `src/settings.js` | Settings in `settings.json`, validated against a schema on every read |
| `src/tray.js`, `src/dnd.js`, `src/focus.js` | Menu bar/tray icon, pausing notifications, focus schedule |
| `src/lock.js`, `src/password.js` | App lock: scrypt hash, Touch ID, auto-lock, throttling |
| `src/overlay.js`, `src/settings-window.js`, `src/ui/` | The app's own pages: lock and recovery screens, settings window |
| `src/recovery.js` | Reconnect after network failures, reload after crashes and hangs |
| `src/updater.js` | Opt-in update check and checksum-verified release downloads; the only code that uses the network |
| `src/self-update.js` | Installs a downloaded update: install detection, unpack and check, swap helper |
| `src/screen-share.js` | Screen-share source picker for `getDisplayMedia()` |
| `install.sh`, `install.ps1` | One-line installers |
| `Casks/thrum.rb`, `scripts/packaging.js` | Homebrew cask and winget manifests, regenerated by the release workflow |

Facebook runs in sandboxed, context-isolated views with no preload and no IPC; the app only injects CSS. The app's own pages (lock screen, settings) have their own preloads, and their IPC accepts only a fixed list of actions from their own page. Builds enable cookie encryption and disable Electron's Node and inspector entry points with fuses, and packaged builds refuse remote-debugging, proxy, DNS-rewrite and certificate-override switches.

### Route policy

All navigation rules are in `src/routes.js`:

- `ALLOWED_PREFIXES`: paths that stay in the app (messaging, calls, login, checkpoint, 2FA, recovery, the photo viewer).
- `FEED_PATHS`, `FEED_PREFIXES`: paths that bounce back to the inbox.
- `downloadTarget()`: attachment URLs that are downloaded, never rendered.
- Anything else opens in the browser.

If a login, security or call step ever ends up in the browser, add its path prefix to `ALLOWED_PREFIXES` and a case to `test/routes.test.js`.

## Releasing

```bash
npm version patch            # or minor; bumps package.json, commits and tags vX.Y.Z
git push --follow-tags
```

`.github/workflows/release.yml` then:

1. builds on macOS, Windows (x64 and ARM) and Linux, and smoke-tests the installers;
2. publishes the GitHub release with `SHA256SUMS.txt` and a build attestation for every file;
3. updates `Casks/thrum.rb` on `main` and attaches winget manifests;
4. installs the published release every supported way (install.sh, Homebrew, install.ps1 on x64 and ARM, apt) to confirm it works.

The workflow fails if the tag does not match `version` in `package.json`. Running it by hand from the Actions tab builds and smoke-tests without publishing.

Apps from v0.4.0 on find the new release through the in-app updater, which downloads the asset for their platform by its file name (`Thrum-<version>-mac-<arch>.zip`, `-win-<arch>.zip`, `-win-<arch>-setup.exe`, `-linux-x86_64.AppImage`). Keep these names stable.

**winget:** the first submission to [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs) is manual (`wingetcreate submit <manifest folder>`, using the manifests attached to the release). Once accepted, add a repository secret `WINGET_TOKEN` (a token with `public_repo` scope) and later releases are submitted automatically.

## Pull requests

Keep changes small and focused, add or update tests, and run `npm test` before pushing. Dependencies: the app has no runtime dependencies, and new ones need a strong reason. GitHub Actions are pinned to commit SHAs and kept current by Dependabot.
